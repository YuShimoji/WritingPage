# 別端末での候補確認（任意・この環境からは起動しない）

このプロジェクトの残タスク・推奨タスクについて分析を依頼しました。添付のログから、適切に新規スレッドを作成し、割り振ってください。

この環境での新規セッションが必要な場合、そのまま作成してください。他環境についてはユーザー側へPromptを渡してください。可能な部分は軽量モデルの新規チャットへ分担し、編集担当が重複しない構成にしてください。

これは上記依頼に対する別環境用Promptです。WritingPage のリポジトリ編集、実装、commit/pushは担当しません。この端末のcheckoutの docs/CURRENT_STATE.md live block と docs/verification/2026-11-02/ci-package-verification.md を読み、Planner007で生成した候補と同一の成果物を使って、端末差の技術確認をしてください。後者がまだ無い場合は候補未提供として待ち、旧packageを代用しないでください。

きっかけとなった観察原文（添付ログ）:
「Electron 候補パッケージは本端末に存在するが、内蔵 markdown-it は 14.1.0、main は 14.3.0 で差異がある。」
「実行環境の npm は 10.9.3 であり、指定の 11 系と乖離している。」
これらはPlanner007の当時の観察であり、別端末の状態と断定しません。保存・変換4件は99c62699でmainに統合済みです。新packageがその修正を含むかはsource SHAとapp.asarで照合します。

1. まず所要時間の幅・不確実な候補取得待ちをチャットで示す。ローカル絶対パスはその端末の実物から解決する。新しいUIは作らない。
2. 候補のsource SHA、成功CI、exe SHA256、app.asar SHA256、梱包版を元記録と照合する。候補フォルダ一式の既存受渡しを使い、受渡し手段が無い場合は必要な候補パス/同一性情報だけを質問する。独自に再buildしたものを同一packageの確認にすり替えない。
3. プロジェクトの安全な起動導線を使い、テスト専用profileと架空原稿で起動→入力→保存→終了→再起動→復帰を確認する。既存の本人データ・通常起動先・元のcheckpointやoperator sheetは変更しない。
4. 削除Wiki復活、遅延IDB巻き戻り、空H2、11個目の揃え付き段落の確認結果は、確認できた範囲だけPASS/FAIL/HOLDで返す。再現不能な条件は未確認。人の操作感（empty hint/現在marker/selection focus等）やWP-004 manual parityを助手の操作だけで受入済みにしない。本人の感想がある場合のみ、その原文と本人観察であることを保持する。

返却はこのチャットで、実環境、候補identity、profile、操作と結果、証跡の絶対パス、未完と再開条件を報告する。リポジトリは読み取り専用のまま。他端末や親チャットへ自動送信せず、この結果をユーザーが元の分担チャットへ渡せる形にする。正式配布・公開・既定起動先への切替は範囲外です。
